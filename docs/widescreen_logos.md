# Widescreen Intro Logos

## Symptoms

On widescreen displays (16:9, 16:10, 21:9 …) the logo screens shown at startup —
the Lionhead / EA logo stills, and the pre-intro video where present — are stretched
horizontally instead of staying 4:3.

On 4:3 and 5:4 displays everything looks fine.

## Cause

The logo screens are two functions in `logo.cpp` (names from bw1-decomp):

| function | vaddr | plays |
|----------|-------|-------|
| `PlayPreIntroVideo` | `0x006426F0` | `\data\pre_intro.bik` (skipped when the file is absent) |
| `PlayLogoScreens` | `0x00642950` | frames 1–3 of `\data\logo.bik` — one logo still per frame, faded in/out with a `Zoomer` |

Both pass the **raw screen size** as the Bink destination rect:

* `PlayLogoScreens` @ `0x00642CDB..0x00642D00` reads the screen width/height globals
  (`0xE85058` / `0xE8505A`, the same ones the [loading-screen fix](widescreen_loading.md)
  uses) and calls the immediate Bink blitter `0x00845740` with
  `(colour|fade, x=-1, y=-1, w, h, 0, 0)`;
* `PlayPreIntroVideo` @ `0x0064286F..0x006428A1` does the same through the persistent
  param setter `0x008456C0` with `(white, 0, 0, w, h, 0, 0)`.

The blitter scales each axis independently (`destW / videoW`, `destH / videoH`, see
the `fild`/`fidiv` pair at `0x008457B9`), so the 4:3 video adopts the screen's aspect
ratio and stretches.

## Fix

Redirect each call-site layout block into a small code cave that computes the same
effective 4:3 width as the loading-screen fix

```
cw   = min(w, h * 4/3)
xoff = (w - cw) / 2
```

and passes `(x + xoff, y, cw, h)` as the destination rect instead of `(x, y, w, h)`.
The pillarbox bars stay black because both functions clear the back buffer through
`LH3DRender::StartFrame` every frame.

On 4:3 and 5:4 displays `cw == w` and `xoff == 0`, so the call is bit-for-bit
identical — including `PlayLogoScreens`' original `x = -1` one-pixel overscan, which
becomes `xoff - 1`.

The shared Bink blitter is deliberately **not** patched: its other callers — the
in-game movie player (`0x0054DC6D`) and the loading-screen movie path (`0x005F410A`)
— compute their own destination rects (the former even has its own letterbox-bar
logic), so a blitter-wide aspect clamp could fight them.

The two caves (73 + 80 bytes at `0x008A8BA0` / `0x008A8BF0`) sit in the `.text` tail
zero-pad after the [`widescreen_loading`](widescreen_loading.md) and
[`windowed_screen_capture`](windowed_screen_capture.md) caves; the patches are
independent and can be applied in any order.

Bytes are generated by [`scripts/widescreen_logos_asm.py`](../scripts/widescreen_logos_asm.py)
(keystone). Each hook op's `expect` is the entire original block, so the patch
refuses to apply to anything but a matching executable.

## Out of scope

The main intro movie and in-game cutscenes go through the in-game movie player,
which sizes its rect from its own globals — if it misbehaves on widescreen it needs
its own investigation, not this patch.
